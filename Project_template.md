# Задание 1. Анализ и планирование

**Уточнения по терминологии
В задании указаны модули управления приборами и так же сами приборы (устройства). Однако, в рамках разных предложений, термин "устройства" фигурирует в разных вариантах. Далее примеры из текста задания**

- Пользователь самостоятельно выбирает необходимые ему модули умного дома (устройства)
- Модули управления приборами и сами приборы (устройства)

**В рамках данной задачи буду использовать термин "устройства" со следующим смыслом: устройства - это датчики/модули управления/реле и любые другие виды подключаемой периферии, которые подключаются пользователем и имеют доступ к серверу "Тёплого дома" через домашнюю точку доступа (роутер).**

## AS IS

### 1. Описание функциональности текущего приложения

**Пользовательский опыт**

- У пользователя есть интерфейс для управления отоплением в доме
- Пользователь имеет возможность просмотреть через интерфейс текущую температуру в доме

**Подключение новых устройств**

- Подключение нового устройства выполняется через выезд специалиста по подключению системы отопления к пользователю
- Подключение нового устройства требует его ручного (или полуавтоматического: через скрипты) внесения идентификатора в базу данных 

**Взаимоедйствие между устройством и сервером**

- Любое взаимодействие между устройством и сервером происходит через синхронный http запрос

**Устройства**

- Каждое текущее устройство имеет уникальный идентификатор, которое используется при вызове бэк приложения "теплого дома"

### 2. Анализ архитектуры монолитного приложения

- Текущее приложение реализовано на языке Java 17
- Используется spring boot
- Архитектура java приложения - Layered Architecture
- База данных - postgresql
- Тестирование: используются unit тесты MockMvc + test container
- Используется docker для развёртывания приложения

### 3. Определение доменов и границы контекстов будущего приложения

- Домен - Удалённое управление устройствами умного дома пользователем 
- Контексты:
  - Управление устройствами IoT
  - Анализ данных с устройств IoT
  - Подключение устройств IoT
  - Пользовательские сценарии 
- Ограниченные контексты
  - Сервис управления IoT
  - Сервис телеметрии с IoT
  - Сервис по подключению новых IoT устройств
  - Сервис CRUD пользовательских сценариев и их запуск

**Пояснение: такое разбиение было выбрано из-за того, что в рамках каждого из контекстов должно быть своё понимание "устройства"**


### **4. Проблемы монолитного решения**

- Отказоустойчивость: при сбое в текущем приложении падает весь функционал "теплого дома"
- Масштабируемость: нет возможности управлять отдальными функциями приложения для масштабирования при росте нагрузки на одну из функций 
- Доступность: при необходимости внесения в текущий функционал новых фич, необходимо заново собирать всё приложение, что увеличивает простои
- Единая точка отказа со стороны базы данных
- Подключение нового функционала в рамках монолитного приложения делает доставку новых фич слишком длительным процессом
